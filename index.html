Skip the Wrapper

Making a browser-automation CLI faster — five candidate optimizations, measured under accounting rules that stop a change looking faster by quietly doing less.

The command on your PATH is not the tool. It is a 41-line Node script that resolves a platform package and execs the real binary, so every invocation is two process spawns and the first is a runtime boot — paid before any browser work begins.

Two real journeys: flat (6 commands, a practice shop) and navheavy (7 commands, saucedemo). Positive is faster. The bar is scaled to the largest magnitude measured — the 740ms loss.

How the figures are kept honest

The board will not build if it disagrees with the evidence base. The evidence base is then checked three ways that are not the same thing.

Resolve

Every pointer opens — file, line range, commit. Cheap, and proves nothing about content.

Quote

The cited line still contains the figure claimed. This is the one that catches a figure broken by a later edit somewhere else.

Math

The arithmetic the prose rests on: 118 − 10 = 108, a stated loss is negative in the data, the sweep's spread matches its runs.

Fit

Both artifacts are measured against the paper they declare. Validated by planting violations and watching them fail.

One ratio may be quoted, and it is not the big one. Removing a runtime boot from a near-empty command is 11.6×, because ~92% of that call is Node boot. On real journeys the same change is 1.33× and 1.69×. A ratio inherits its denominator, so absolute milliseconds lead throughout.
